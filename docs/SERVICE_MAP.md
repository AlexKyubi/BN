# Bonus Navigator — карта проекта и работы сервиса

Дата актуализации: 09.09.2026.
Текущий релиз: frontend `1.3.0`, backend `2.1.0`, release ID `2026.09.09.4`.

Это публичная техническая карта без секретных значений. Не записывайте сюда пароли, токены,
секрет подписи, приватные URL и их фактические значения.

## 1. Назначение

Bonus Navigator состоит из каталога товаров и пользовательского dashboard.

Каталог показывает процент отчисления за выбранный месяц, цену, фотографию и остатки в магазинах
выбранного города. Из карточки можно посмотреть подробности или добавить продажу.

Dashboard показывает аналитику продаж по месяцам, позволяет редактировать продажи и отмечать
возвраты, создавать Excel, переносить историю между устройствами и менять настройки.

## 2. Архитектура

```text
┌──────────────────────────────────┐
│ Браузер / установленная PWA      │
│ GitHub Pages                     │
│                                  │
│ index.html — каталог             │
│ dashboard.html — аналитика       │
│ IndexedDB — история продаж       │
│ local/sessionStorage — настройки │
└──────────────┬───────────────────┘
               │ HTTPS + X-Access-Token
               ▼
┌──────────────────────────────────┐
│ VM: Caddy → Python :8080         │
│ HTTP API, SQLite, фоновые потоки │
└───────────┬───────────┬──────────┘
            │           │
            ▼           ▼
       Sulpak API   Google Sheets
```

CSV-каталог браузер загружает из Google Sheets напрямую. Сервер читает ту же таблицу для списка
отслеживаемых артикулов и метаданных отчёта по остаткам.

### 3.3 Запуск и сетевые обращения

1. Локально проверяются флаг входа, ФИО и сохранённая ссылка таблицы.
2. `/auth/validate` подтверждает ссылку и выдаёт новый `X-Access-Token`.
3. Справочник регионов, CSV и снимок выбранного региона загружаются параллельно.
4. Валидный CSV-кеш применяется сразу; сеть проверяет свежую версию.
5. `/region-stock` отдаёт полный снимок либо дельту по `syncToken`.
6. Карточки получают цены, фотографии и остатки из снимка SQLite.

Таймера обновления каталога нет. Сеть проверяется при обычном открытии/обновлении страницы, при
нажатии информации конкретного товара и при смене региона/города.

### 3.4 Быстрый возврат

- Перед dashboard или характеристиками Sulpak каталог сохраняет сессионный снимок.
- Если регион не менялся, возврат восстанавливает карточки, фильтры и прокрутку без повторных CSV
  и `/region-stock`.
- После смены региона/города каталог открывается штатно и получает снимок нового города, чтобы не
  показать цены предыдущего региона.
- Обычное обновление страницы всегда выполняет стандартные проверки сети и авторизации.

### 3.5 Производительность каталога

Пагинации и виртуального списка нет: каталог рассчитан примерно до 1000 карточек, а сортировка
применяется ко всему набору. Для ускорения используются:

- единый словарь остатков на проход и `DocumentFragment`;
- `content-visibility: auto` для невидимых карточек;
- `loading="lazy"` и `decoding="async"` для изображений;
- один общий SVG-placeholder;
- мгновенный показ свежего CSV-кеша без ожидания Google Sheets.

### 3.6 Хранение на устройстве

| Хранилище | Данные |
|---|---|
| `localStorage` | Вход, токен, введённый URL таблицы, регион/город, фильтры, месяцы, сортировка, тема и состояние версии |
| `sessionStorage` | Быстрый снимок каталога, прокрутка, остатки и одноразовые маршруты возврата |
| `IndexedDB` | История продаж пользователя |
| Cache Storage | Только оболочка PWA |

История продаж не отправляется на backend. Перенос выполняется JSON-файлом. Импорт проверяет
формат, даты, числа и ограничения, объединяет записи по ID и оставляет более новый `updatedAt`.

## 4. Google Sheets

| Колонка | Индекс | Назначение |
|---|---:|---|
| B | 1 | Запасной источник категории |
| C | 2 | Артикул |
| D | 3 | Название модели |
| E и далее | 4+ | Месячные проценты отчислений |

Колонки с E до конца считаются месяцами. Выбранная колонка определяет процент и число звёзд:
`3%` отображается как 3 звезды, максимум — 5.

CSV-кеш живёт 6 часов. Порядок: свежий кеш для первого показа → прямой запрос → CORS-прокси при
ошибке → локальный fallback, если он существует. Совпавший сетевой CSV повторно не разбирается.

## 5. Dashboard и продажи

Dashboard ориентирован на выбранный месяц и содержит сумму продаж, число товаров, начисление,
сравнение с прошлым месяцем, график по дням, категории, последние операции и полный список.

В истории есть независимые фильтры по артикулу и календарной дате. Редактирование открывается
осознанным нажатием; доступны дата, цена, количество и только два статуса: продана/возвращена.

«Пользовательские настройки» содержат оттенок акцента, регион, город, фильтры каталога и отчёт по
остаткам. При смене региона/города dashboard вызывает `/region-stock`: во время запроса показывает
красный статус, затем подтверждение и число записей. Эндпоинт читает SQLite; полная загрузка Sulpak
происходит только для ещё не инициализированного региона.

Единый блок «Отчёты и данные» содержит:

- «Поделиться Excel» — системное меню отправки; при его отсутствии файл скачивается;
- «Экспорт данных» — JSON-копия всей истории;
- «Импорт данных» — проверка и объединение JSON с текущей историей.

Excel формируется на устройстве: лист «Итоги» и отдельный лист каждого месяца. Возвращённые продажи
в отчёт не включаются.

## 6. Backend на VM

### 6.1 Размещение

- приложение: `/opt/bn-proxy`;
- systemd-сервис: `sulpak-proxy.service`, пользователь `www-data`;
- Python слушает `127.0.0.1:8080`;
- Caddy принимает HTTPS и проксирует к Python.

Пути из `server/data/server_config.json` вычисляются относительно рабочей директории процесса.

### 6.2 Модули

| Модуль | Ответственность |
|---|---|
| `proxy_server.py`, `bootstrap.py` | Запуск и справочные данные |
| `config.py` | JSON-конфигурация и переменные окружения |
| `web_handler.py` | HTTP, CORS, токены и безопасные ошибки |
| `store.py` | SQLite, схема, очередь и бэкапы |
| `sulpak_client.py` | Получение и нормализация Sulpak |
| `backfill_photos.py` | Разовая миграция фотографий для старых записей |
| `csv_sync.py`, `regions.py` | Артикулы CSV и справочник регионов |
| `sheet_auth.py`, `access_token.py`, `report_auth.py` | Проверка доступа |
| `rate_limit.py`, `concurrency.py` | Лимиты и single-flight |
| `errors.py`, `utils.py` | Типы upstream-ошибок и серверные преобразования |
| `release_info.py`, `logging_setup.py` | Версии и логирование |
| `services/stock_service.py` | Bootstrap региона, TTL и один товар |
| `services/background_refresher.py` | Регулярное обновление остатков |
| `services/maintenance.py` | CSV-сверка и ежедневный бэкап |
| `services/report_service.py` | Excel по остаткам |

### 6.3 SQLite

| Таблица | Назначение |
|---|---|
| `tracked_articles` | Артикулы, названия, категории и CSV-строки |
| `regions` | Города и регионы |
| `region_state` | Признак первичного заполнения региона |
| `stock_records` | Цена, фото, остатки, магазины, ошибки, времена, `sync_token` |
| `refresh_queue` | Повторные попытки после ошибок Sulpak |
| `meta` | Глобальный sync-токен и даты обслуживания |

SQLite: WAL, `synchronous=NORMAL`, busy timeout и автоматический checkpoint. При старте добавляются
недостающие таблицы/колонки и удаляется таблица старой функции просмотров.

### 6.4 Остатки

1. Первое обращение к неинициализированному региону загружает все отслеживаемые товары и отмечает
   регион инициализированным. Single-flight исключает параллельный дубль.
2. После инициализации снимок региона всегда читается из SQLite.
3. Фоновый поток обновляет по одной паре регион/артикул и распределяет полный круг примерно на
   три часа в пределах рабочих часов.
4. Каждое нажатие на кнопку информации вызывает `/stock`.
5. Backend возвращает свежую SQLite-запись либо, если `lastSuccessAt` старше TTL, обновляет только
   этот товар с причиной `user_request`.
6. Ошибка Sulpak сохраняется и ставит товар в `refresh_queue`.

TTL проверяет backend. Клиентского TTL и периодического запроса `/stock` нет.

### 6.5 Фоновые задачи

- остатки: полный круг около 3 часов в рабочих часах;
- список артикулов: сверка раз в 3 часа;
- SQLite: ежедневный backup, автоматическое хранение 3 дня;
- maintenance polling: раз в 5 минут.

## 7. HTTP API

| Путь | Доступ | Назначение |
|---|---|---|
| `/` | публичный | Минимальный статус |
| `/health` | публичный | Только `ok`, `status`, `release.id/frontend/backend` |
| `/auth/validate?sheetUrl=…` | публичный, с лимитом | Проверка ссылки и выдача токена |
| `/regions` | `X-Access-Token` | Регионы и города |
| `/region-stock?cityId=…&languageId=…&since=…` | токен | Полный/дельта-снимок SQLite |
| `/stock?cityId=…&article=…&languageId=…` | токен | Один товар с серверной проверкой TTL |
| `/region-stock-report?...` | токен + `X-Report-Password` | Excel по остаткам |

Ошибки: `400` параметры, `401` токен/пароль, `403` запрещённая ссылка, `404` неизвестный ресурс,
`429` лимит/блокировка, `503` отчёт не настроен, `500` внутренняя ошибка без traceback, SQL,
локальных путей и деталей upstream.

## 8. Доступ и безопасность

- CORS ограничивает браузерный origin, но не заменяет авторизацию.
- Защищённые данные требуют подписанный токен; стандартный срок — 7 дней.
- Dashboard имеет локальную проверку входа, а его API-запросы всё равно требуют токен.
- Отчёт по остаткам дополнительно защищён PBKDF2-хешем и блокировкой перебора.
- Пароль отчёта вводится в модальном окне и клиентом не сохраняется.
- `/health` не раскрывает размеры, пути, IP, метрики БД или конфигурацию VM.
- Лимит: 180 запросов на IP за 60 секунд; `/` и `/health` не учитываются.

Фактические `access_token_secret`, `report_password_hash`, разрешённый URL таблицы и пароли должны
оставаться только в закрытом конфиге VM/локальной копии. Их нельзя добавлять в Git, frontend-архивы
или документацию.

## 9. Логи и дисковое пространство

| Назначение | Ограничение |
|---|---|
| `logs/proxy_server.log` | 5 МБ + пять архивов; полный INFO/WARNING/ERROR |
| `logs/rate_limit.log` | 1 МБ + два архива; отдельный учёт 429 |
| systemd journal | От приложения только WARNING/ERROR; служебные события systemd остаются |
| `backups/*.sqlite3` | Ежедневные копии с retention 3 дня |

Ключевые события: `api_request`, `api_success`, `api_error`, `sqlite_response`, `access_denied`,
`rate_limited`, `tracked_csv_refreshed`, `background_cycle_done`, `backup_done`.

## 10. Отчёт по остаткам

Кнопка находится в «Пользовательских настройках» dashboard. После выбора региона/города
пользователь вводит пароль, который передаётся только по HTTPS в `X-Report-Password`.

Имя файла: `report ДД-ММ-ГГ.xlsx`. Содержимое: категория, артикул, модель, процент и звёзды
выбранного месяца, цены, количество, статус, время обновления и отдельные колонки магазинов.

## 11. Релизы и обновление клиента

`server/data/release.json` содержит только публичные строки `id`, `frontend` и `backend`.
Клиент проверяет `/health` один раз при старте страницы. Кнопка «Обновиться» появляется при новой
версии frontend или ещё не подтверждённой версии backend. Она очищает только оболочку PWA,
обновляет service worker и перезагружает страницу; авторизация и продажи сохраняются.

При frontend-релизе синхронно обновить:

1. `FRONTEND_VERSION` в `assets/scripts/config.js`;
2. `bn-frontend-version` и `?v=` в `index.html`;
3. CSS/JS `?v=` и текст версии в `dashboard.html`;
4. `CACHE_NAME` и URL прекеша в `sw.js`;
5. `frontend` и `id` в `server/data/release.json` на VM.

При backend-релизе изменить `backend` и `id`. Backend перечитывает release-файл без рестарта.

## 12. Развёртывание

### Frontend

Публикуются `index.html`, `dashboard.html`, `assets/`, `public/manifest.json`, `sw.js` и `CNAME`.
Папки `server/`, `deploy/`, `docs/`, `data/`, `logs/`, `backups/`, `trash/`, `.dev/` и выгрузки
пользователей исключены в `.gitignore`.

### Backend

Обновление VM:

1. проверить архив во временной директории;
2. создать точечный backup заменяемых файлов и конфига;
3. остановить `sulpak-proxy`;
4. установить файлы с корректными владельцем и правами;
5. выполнить `py_compile` и чтение конфига от `www-data`;
6. запустить сервис;
7. проверить status, локальный/публичный `/health` и journal.

Не применять ZIP, создающий обратные слеши в Linux-именах. Использовать корректный ZIP с `/` либо
`tar.gz`. Подробности находятся в `deploy/DEPLOY_VM.md`.

### Локальный запуск

```powershell
$env:ALLOWED_ORIGINS="http://127.0.0.1:5500,http://localhost:5500"
python server/proxy_server.py

# В другом терминале
python -m http.server 5500
```

Открывать `http://127.0.0.1:5500/index.html`. Через `file://` ES-модули и PWA могут работать
некорректно. Для локального backend временно меняют `DEFAULT_PROXY_BASE`, а перед публикацией
обязательно возвращают production-адрес.

## 13. Эксплуатационные правила

- Новый хеш пароля отчёта: `python server/report_auth.py`; сам пароль нигде не записывать.
- Отозвать все токены: заменить `access_token_secret` и перезапустить сервис.
- SQLite проверять через `PRAGMA integrity_check` от пользователя сервиса.
- Перед очисткой journal сначала ограничить его дальнейший рост, затем использовать штатные
  `journalctl --rotate` и `--vacuum-size`.
- `trash/` не удалять: это локальная ручная корзина проекта.
